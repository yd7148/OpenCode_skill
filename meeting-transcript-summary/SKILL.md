# meeting-transcript-summary — 原始時間戳會議逐字稿 → 詳盡繁中會議彙總

把語音辨識（Whisper/faster-whisper 等）產出的「每行一段、帶時間戳」逐字稿
（如 `2026-08-31 08-25-42_timestamp.txt`）彙總成 **詳盡繁體中文主管會議紀錄**，
交付為 `<BASE>_會議彙總.md`（同一專案資料夾）。輸出須「條列各主管問題與部屬答覆」
並「列出指示／須完成目標與代辦事項」。

## When to use
- User 給你一個 `*_timestamp.txt`（或任一語音辨識逐字稿），要求「彙總會議紀錄」
- 要求「詳細彙總、條列各主管問題與部屬答覆、指示須完成目標與代辦事項」
- 需要把長達數小時的半導體／製造業／任何專業會議逐字稿，濃縮成可讀的會議紀錄

## 核心原則
1. **完整讀完才動筆**：`read` 用 offset 分頁讀完整個檔案；不要只讀開頭。
2. **語音辨識會誤聽**：以專業上下文研判「更正常見誤聽詞」，**在摘要中直接改正**，
   不照抄雜訊。彙總開頭以引言區塊列出已更正之對照表。
3. **不失真**：只根據逐字稿內容撰寫，不自行發明會議沒提到的資訊。
4. **詳盡**：user 要求「更詳細」時就擴寫——每個議題補背景、原因、主管論述脈絡。

## 已知誤聽詞對照（半導體/製造業語境，隨專案持續增補）
- 掌精爐/掌金爐＝長晶爐、掌金/長晶＝長晶、漲晶＝長晶、潔晶＝結晶
- 死檵/石刻/石穿＝蝕刻、螺牙/來拉/羅牙＝螺牙、來拉/撓牙＝螺牙
- TAC/TA系/貼器/搏貼器＝TAC 塗層、PVA/PBA＝PVA（爐廠）、竹内＝塗內(竹內)、陶下/淘下＝塗下(陶下)
- 金擊＝台積電、火台辦/國財辦＝國台辦、Cicola＝新耀半導體、拿配＝(廣)運
- （非半導體語境類比：測試測試＝測試、Open call/ocal＝OpenCode、Power share＝PowerShell 等）

## 工作流程
### 1. 讀完逐字稿
`read` 設 `offset` 依內容長度分頁（每頁約 1200–1800 行）直到「End of file」。
注意：檔案可能極大（數十萬字元），output 超過 50KB 會截斷 → 一定用 offset 續讀。

### 2. 判斷產出格式
- 一般要求：寫成結構化繁中摘要（見下方「輸出結構」）。
- 要求「更詳細/更多敘述與描述」：把每個議題擴寫成多小節（背景→主管提問→
  部屬答覆→主管裁示→代辦），補足論述脈絡與決策緣由。

### 3. 輸出結構（繁中）
1. `# <日期> 會議紀錄彙總`（詳盡版加「（詳盡版）」）
2. 引言區塊：來源檔名、領域、主要人員、時長、誤聽詞更正對照表、時間軸說明
3. `## 一、會議開場與人員動態`（主持、與會、出差/來賓動態）
4. `## 二、主管指示與部屬答覆`（每議題一小節：標明「主管提問/說明」與「部屬答覆」；
   若有明確「主管裁示」另以粗體標出重要方針）
5. 依會議內容延伸：異常通報、簡報/技術報告、產業情報、決策
6. `## 目標與代辦事項彙總（Action Items）`：**表格**（#、事項、負責/對象、期限）
7. `## 備註`：來源、誤聽更正說明、附屬交付

### 4. 儲存與驗證
- 檔名：`<BASE>_會議彙總.md`（`<BASE>`＝來源檔名去 `_timestamp.txt`，即
  `2026-08-31 08-25-42` → `2026-08-31 08-25-42_會議彙總.md`，或依專案慣例命名的中文名）
- 一律 `write` tool 建立，UTF-8；寫完用 `read` 回讀前幾行確認無亂碼/斷句。
- 中文檔名在 PowerShell 下 `-LiteralPath` 引號包裹才能操作。

## Deliverables checklist
- [ ] 完整讀完來源逐字稿（含 offset 續讀）
- [ ] `<BASE>_會議彙總.md`（UTF-8，內容經 Read 校對）
- [ ] 各主管問題／部屬答覆已條列清楚
- [ ] 目標與代辦事項以表格列出（含期限）
- [ ] 誤聽詞更正對照表置於開頭引言
